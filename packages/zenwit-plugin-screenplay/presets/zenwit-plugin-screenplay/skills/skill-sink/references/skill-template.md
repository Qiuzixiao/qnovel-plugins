# SKILL.md 标准模板（沉淀新技能时按此格式生成）

> 复制以下骨架，替换 `<...>` 占位符。正文用中文，忠实、具体、可执行。

```markdown
---
name: <skill-name>
description: "<一句话说明这个 skill 做什么 + 什么时候用/触发场景>"
metadata:
  scope: user
  version: 1
  applicableTo: ["<适用场景1>", "<适用场景2>", "<适用场景3>"]
  sourceIds: ["<来源文件绝对路径，若来自对话经验可省略或写沉淀日期>"]
  whenToUse: "<触发词 / 语言信号 / 什么情境下激活>"
---

# <技能标题>

> 一句话内核：这个技能解决什么问题、给谁用。

## 触发场景（什么时候用）
- <场景1>
- <场景2>

## 执行步骤（怎么做，可落地）
1. <步骤1，含完成标准>
2. <步骤2，含完成标准>
3. <步骤3，含完成标准>

## 边界与失败模式（不要做什么 / 容易犯的错）
- <边界1>
- <失败模式1 → 对策>
- <失败模式2 → 对策>

## 示例（可选，正反各一）
- ✅ <正例>
- ❌ <反例>
```

配套的 metadata.json：

```json
{
  "name": "<skill-name>",
  "description": "<同 SKILL.md description>",
  "scope": "user",
  "version": 1,
  "applicableTo": ["<适用场景>"],
  "whenToUse": "<触发词>",
  "referenceCount": 0
}
```

## 质量自检（沉淀前过一遍）
- [ ] 三问全过：可复用？有触发场景？能落地成步骤？
- [ ] name 是语义化 kebab-case（3–6 段小写英文）。
- [ ] description 一句话说清「做什么 + 何时用」。
- [ ] 执行步骤含完成标准，不是口号。
- [ ] 有边界/失败模式，不是只有正面说法。
- [ ] 没有把某一部剧的具体人物/剧情写进去。
