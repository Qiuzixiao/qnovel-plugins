# 技能沉淀（把经验与文风变成可复用技能）

> 目的：让「这一次创作中验证有效的经验」不再丢在对话里，而是固化成 skill，下一次创作自动可用。这是短剧创作 Agent 越用越像用户、越用越强的关键机制。

## 一、什么值得沉淀（三问判定，全过才沉淀）
1. **可复用吗？**——不是某一部剧的一次性设定，而是能套用到下一部的。
2. **有明确触发场景吗？**——能说清「什么时候该用」。
3. **能落地成步骤吗？**——能写成「怎么做」的可执行步骤，而不是一句口号。

> 反例：某一部剧的具体人物/剧情/结局（story-fact）**不沉淀**；「反转要多」这种空泛口号**不沉淀**（缺步骤）。

## 二、两类沉淀

### A. 个人文风 skill（用户资产，越用越像他）
来源：用户投喂的作品/口味/风格偏好、用户反复要求的表达习惯。
内容：题材偏好、情绪标签、节奏偏好、爽感类型、卡点风格、台词口吻、人设风格。
沉淀方式：**少量多次**，每样带一句「为什么喜欢 / 哪段最戳我」；冷门作品学「感觉」用类型词、学「事实/设定」喂原文底子。

### B. 经验方法论 skill（创作经验固化）
来源：创作中验证有效的手法、一次成功改稿的诊断方法、用户反复强调的规则、踩过的坑。
内容：触发场景 + 执行步骤 + 边界/失败模式。

## 三、触发时机（主动识别）
- 用户明确说「记住这个 / 以后都这样 / 沉淀成技能 / 存成我的风格」。
- 创作中同一偏好/手法出现 ≥2 次。
- 一次改稿后总结出「可复用的诊断/修改方法」。
- 用户投喂了一批作品/口味素材。

## 四、沉淀流程（对话式，先确认、不擅自写）
1. **发现候选** → 用一句话向用户确认：「我发现 X 可以沉淀成技能，要不要固化下来？」
2. **共同提炼** → 与用户确认四项：名字、一句话用途、触发场景、执行步骤与边界（用户有最终拍板权，不得擅自替用户决定文风）。
3. **生成文件** → 按 `references/skill-template.md` 生成 SKILL.md + metadata.json。
4. **写入** → 写入用户 skills 目录 `${DSH_HOME:-$HOME/.zenwit}/skills/<skill-name>/`（文风与经验都是用户资产，放用户根，不放进某一 preset）。
5. **回执** → 告知用户已沉淀，说明「下次创作会自动可用」。

## 五、skill 命名与结构约定
- name：3–6 段小写英文 kebab-case，语义化（如 `personal-dialogue-style`、`rewrite-cold-open`）。
- 目录结构：`<skill-name>/SKILL.md` + `<skill-name>/metadata.json`（+ 可选 `references/`）。
- 已有相似 skill 时**更新而非新建**（避免碎片化）。

## 六、边界
- 不擅自沉淀：必须先向用户确认，用户文风/经验是用户的资产。
- 沉淀「方法论」而非「某部剧内容」：story-fact 不进 skill。
- 版权/隐私内容不沉淀，提前想清楚哪些能固化。
- 沉淀是「少量多次」，不追求一次灌满。

## 七、与初始技能的冲突裁决

用户沉淀的技能（`personal-*` / 自定义经验技能）与初始方法论 skill 冲突时，按以下优先级裁决：

- **E级默认值 / 文风口味**：用户技能无条件优先，直接覆盖。
- **P级硬规**（反转≥2、主角在场、付费闸门位置等）：用户技能可覆盖，但必须在 skill 里显式写明「覆盖了哪条 P级 + 理由」，即工单特批。
- **H级红线**（尊严条款、付费公平性、切点纪律、恨账专户律）：不可覆盖；沉淀时若与之冲突，以 H级为准，并提示用户调整。
- 沉淀时若与已有 skill 语义重叠，**更新而非新建**，避免碎片化与互相打架。
