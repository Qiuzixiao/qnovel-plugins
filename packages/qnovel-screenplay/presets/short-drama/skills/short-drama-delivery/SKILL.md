# 面向平台的短剧交付与商业准备

## R — 原文（Reading）

> “在这个时代，服务观众是我们要放在第一位的。”
>
> — 查理，《写好短剧》“生活中的故事”

## I — 方法论骨架（Interpretation）

把剧本视为平台和观众共同验收的产品。先明确目标平台、受众和类型，再把最大冲突/最大卖点压缩进标题和一句话梗概，形成可被快速判断的提案。交付包应让对方看见：主角诉求、持续冲突、分集卡点、制作条件和作者能承担的工作。对接时记录版本、署名、修改范围、交付节点和付款条件；行业经验可辅助判断，但合同条款必须单独审核。

## A1 — 书中的应用（Past Application）

### 茶道与豆腐乳

- **问题**：同样的产品为何形成完全不同的产业价值？
- **方法论的使用**：用故事包装、权威与传播把普通消费品变成可溢价的文化产品。
- **结果**：说明故事上游掌握卖点定义和资源回流。

## A2 — 触发场景（Future Trigger）★

1. 用户已有短剧创意，想整理成平台投稿或制片人可快速判断的提案。
2. 需要为同一项目写标题、卖点、受众、分集卡点和交付清单。
3. 询问如何进入行业、对接编剧工作或准备商业合作。

### 语言信号

- “帮我做短剧投稿包/项目提案”
- “这个故事卖点是什么，标题怎么取”
- “怎么和平台/制片方对接、避免踩坑”

### 与相邻 skill 的区分

- 与 `short-drama-ideation`：本 skill 假设已有可讲清的创意，负责包装交付，不替代故事开发。
- 与 `short-drama-hook`：本 skill 处理项目级卖点和材料，后者设计具体戏内卡点。
- 与 `short-drama-revision`：本 skill 检查交付可用性，不做全稿文学/结构修改。

## E — 可执行步骤（Execution）

1. **锁定市场假设**：记录平台形态、目标观众、类型、时长/集数、审查和制作限制；不确定项标为待验证。
2. **压缩卖点与材料**：生成标题、logline、主角目标/缺失、核心对手、前 3 集钩子、全季升级和制作亮点。
3. **形成对接包**：列出梗概、人物表、分集大纲、样章、作者简介、版权/署名和版本清单，并把商业承诺与法律风险分开。

## B — 边界（Boundary）★

- 不要把未经验证的平台规则、报价或“必过审”说法当事实。
- 不替用户签约、承诺收益或提供正式法律意见；合同、版权和付款条款需专业人士审核。

### 失败模式与盲点

- 只顾作者表达、拒绝类型爽感，导致卖点不清。
- 标题文艺却不呈现最大冲突；把故事包装成焦虑贩卖而缺乏真实价值。

### 作者盲点

书中商业建议依赖个人行业经验，未覆盖不同平台、地区、预算和新型 AIGC 协作模式，交付时必须现场核验。
